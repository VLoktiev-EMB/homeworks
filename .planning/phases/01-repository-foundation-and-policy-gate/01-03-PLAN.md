<objective>
Stand up the two-directional secret gate: gitleaks on staged changes locally
(pre-commit, blocking the commit) and gitleaks over the full history in CI on every
pull request (catching a bypassed local hook). Neither direction alone covers both
failure modes (RESEARCH Architectural Responsibility Map).

Purpose: FOUND-07 is the phase's hardest irreversibility guard — a secret in public
history cannot be scrubbed under D-12, so detection must exist before the first public
push.

Output: the pinned hook config, the single Phase 1 workflow, and a token-level contract
test that keeps the workflow's critical flags from silently drifting.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer workstation → public history | the staged-changes hook is the last local chance to stop a secret; bypass via --no-verify must be caught by the CI direction |
| CI runner → public logs | a detected secret is sensitive inside the build log itself; redaction is mandatory |
| third-party code → hook execution | pre-commit hooks ship executable code from pinned revisions chosen at plan time |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-02 | Information Disclosure | secret committed and pushed to public repo | critical | mitigate | two-directional gate: gitleaks pre-commit hook (staged, redacted) + full-history CI scan on every PR with push protection enabled server-side (plan 01-01 task 3); incident rule is rotate-first, forward-fix, document — never history rewrite (D-18), codified in AGENTS.md by plan 01-06 |
| T-1-05 | Tampering | supply chain via hook/workflow definitions | medium | mitigate | every hook rev pinned to an immutable tag (v8.30.1, v6.0.0); CI installs gitleaks from a version-pinned release URL; the hosted gitleaks GitHub Action is deliberately not used (org license requirement, Pitfall 7) and its slug is contract-tested absent |
| T-1-08 | Information Disclosure | secret value reaching CI logs | medium | mitigate | --redact on every gitleaks invocation (pre-commit entry and CI step); no GITHUB_TOKEN is ever added to a hook; the contract test asserts the flag's presence |
| T-1-SC | Tampering | package installs (implied by hook builds) | high | mitigate | package-legitimacy gate satisfied: gitleaks 8.30.1 and pre-commit-hooks v6.0.0 both carry verdict OK in RESEARCH §Package Legitimacy Audit (direct GitHub API reads, star counts, MIT licenses) |
</threat_model>
