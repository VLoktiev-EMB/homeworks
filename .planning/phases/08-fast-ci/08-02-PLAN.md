<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| schedule trigger → default-branch checkout | The nightly run executes whatever the default branch contains |
| downloaded release asset → runner | gitleaks arrives over the network |
| git history → job log | A found secret would be printed by a verbose scanner |
| previous runs → cache | The nightly cache seeds the default-branch scope |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-8-07 | Information Disclosure | nightly `secrets` job log | high | mitigate | The scan runs with `--redact`, so a matched secret is masked in the log; the job holds `contents: read` only. |
| T-8-08 | Tampering | nightly `build` commands | high | mitigate | `matrix.project` and `matrix.env` arrive through `env:` and are quoted; no matrix expression is interpolated into `run:` (Pitfall 10). |
| T-8-09 | Tampering | nightly cache | medium | mitigate | The key is derived from the reviewed `platformio.shared.ini` pin and carries no `restore-keys`; only the default branch can seed it (Pitfall 7). |
| T-8-10 | Denial of Service | nightly schedule | low | accept | A 90-minute budget on a free public-repository runner is bounded by GitHub's own concurrency limits; a runaway run is visible as a red nightly and no data is at risk. |
| T-8-SC | Tampering | gitleaks download | high | mitigate | Pinned 8.30.1 with the committed SHA-256 verified before execution; no new pip dependency is added by this plan. |
</threat_model>
