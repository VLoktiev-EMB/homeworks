**The shape to copy is `scripts/new_homework`.** Compute every rendered file in memory, classify
every target, print one `PATH: STATUS — reason` record per target, and only then write (Pattern 1
in RESEARCH). The differences are: the status vocabulary, the manifest, and the target set.

**Status vocabulary — use exactly these names.** `CREATE` (absent, not in the manifest),
`UNCHANGED` (bytes identical), `MODIFIED` (bytes differ, or a manifest-listed path the generator
still produces but which is absent on disk is `DELETED`), `ORPHAN` (manifest-listed, no longer
produced), `DELETE` (write-mode removal of an orphan), `ERROR` (a content problem on an owned
file). Exit 0 when every record is `CREATE`, `UNCHANGED`, `MODIFIED` or `DELETE` in write mode, and
`UNCHANGED` alone in check mode; exit 1 on any `ERROR`, or on any `MODIFIED`, `DELETED` or `ORPHAN`
in check mode; exit 2 on a usage or environment problem, with `ERROR:` on stderr and nothing on
stdout.

**Region ownership (D-14).** A region target's owned bytes are the slice from
`<!-- BEGIN GENERATED: homeworks -->` through `<!-- END GENERATED -->`, both markers included. The
manifest hashes that slice, so an authored edit outside the region is not drift and a moved marker
is. A file with zero begin markers, more than one, or an end marker before the begin marker is a
`CheckError` (exit 2) — the region is ambiguous, which is an environment problem, not drift. A
region target that is absent on disk is an `ERROR` record (exit 1): write mode must never recreate
an authored file and silently drop its prose.

**Manifest shape (D-17).** One JSON object, `{"version": 1, "entries": [...]}`, entries sorted by
`path`, `json.dumps(payload, indent=2, ensure_ascii=False)` plus one trailing newline, no
timestamps and no environment data. Each entry: `path`, `owner` (the subcommand name), `mode`
(`whole` or `region`), `sha256` (lowercase hex of `hashlib.sha256` over the owned bytes), `bytes`;
a region entry also carries `marker_begin` and `marker_end`. The manifest never lists itself:
recompute it and compare bytes with the committed copy, reporting `generated.manifest:
UNCHANGED` or `MODIFIED`. A single-subcommand run rewrites only its own `owner` entries and leaves
every other owner's entries byte-identical.

**`.gitignore` currently ignores `generated.manifest`** through the blanket `*.manifest` rule in
the PyInstaller block. D-17 requires it committed, so add a `!generated.manifest` negation
immediately after `*.manifest`, with a comment citing D-17. Do not touch `site/`,
`compile_commands.json`, `homeworks/*/.gitignore` or any other rule, and do not weaken the
`no-generated-files` hook — none of the paths this phase generates is on its list.

**Orphan deletion (adopted reading of RESEARCH Open Question 3).** Write mode removes a path only
when the previous manifest listed it *and* the file still begins with
`<!-- GENERATED — do not edit. Run: uv run scripts/gen_views.py --all -->`. It reports `DELETE`.
Anything the manifest did not list is never removed, however stale it looks.

**No second YAML writer, no `git remote`, no clock, no PlatformIO.** The site URL and the
repository URL are module constants (`SITE_URL = "https://vloktiev-emb.github.io/homeworks/"`,
`REPOSITORY_URL = "https://github.com/VLoktiev-EMB/homeworks"`), following the `BOARD` constant
precedent at `scripts/new_homework:94`, because a fixture root has no git remote.

**Cell escaping (ASVS V5).** Every value that enters a Markdown table cell escapes `|` as `\|` and
has control characters, tabs and newlines collapsed to a single space first. Never emit raw HTML
from a metadata value.

<threat_model>

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `homework.yaml` values to rendered Markdown | A `title` containing `|`, a newline or raw HTML crosses into a published table cell. |
| Repository tree to generator writes | A symlinked `README.md`, `docs/` or `mkdocs.yml` component would redirect a write out of the intended file. |
| Manifest to deletions | The manifest is the only authority on what may be deleted; a forged or widened entry could authorize removing authored content. |
| `--check` to the working tree | A check that repairs drift would make the drift gate meaningless. |
