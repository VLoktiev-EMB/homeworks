**This plan changes no behaviour.** It is a pure extraction plus two new files. The gate for the
extraction commits is that the existing 81-test suite and `python3 scripts/check_architecture.py`
stay green with no assertion edited to accommodate the move.

**Why `errors.py` exists.** `scripts/metadata/contract.py` imports `yaml` and
`jsonschema` at module scope, and `scripts/tests/` may not import either library (04/D-14). If
`render.py` imported `CheckError` from `contract.py`, any test that imports the renderer would
transitively import PyYAML. Moving the one exception class to `scripts/metadata/errors.py` and
re-exporting it from `contract.py` keeps `from scripts.metadata.contract import CheckError`
working for every existing call site while letting `render.py` and `platformio.py` stay
stdlib-only. Do not create a second exception class and do not define one inside `render.py`.

**Why `platformio.py` is extracted, not copied.** `scripts/check_architecture.py` currently owns
its own `CheckError`, `resolve_root`, `_option`, `_extends_targets` and `_dep_names`, and it has no
`sys.path` bootstrap because it is run as a standalone script. Adding the bootstrap and importing
the shared module is the whole change; the local `resolve_root` may stay where it is (the shared
one lives in `paths.py`). Keep the
function bodies byte-for-byte identical — including the `native` PREFIX rule at
`scripts/check_architecture.py:438-443` and the `name=symlink://` alias rule at lines 464-489 —
because both were review findings (03-REVIEW CR-01, WR-03) and the public names `option`,
`extends_targets`, `dep_names`, `load_ini` are what `scripts/affected.py` will import.

**Why `paths.py` and `yaml_loader.py` exist (blocking review finding).**
`scripts/metadata/contract.py:44-46` imports `yaml` and `from jsonschema import
Draft202012Validator` at module scope. `scripts/gen_views.py` and `scripts/affected.py` declare
only `PyYAML==6.0.3` in PEP 723, and the `gen-views-check` pre-commit hook and the
`generated-views` CI job install only `PyYAML==6.0.3`; importing `contract.py` for
`derive_parts`, `resolve_root`, `relative_path` or `StrictSafeLoader` would therefore fail with
`ModuleNotFoundError` in exactly the environments that must run the gate. Move the four pure
identity/path helpers and the `HOMEWORK_ID` pattern into `scripts/metadata/paths.py` (imports
`pathlib`, `re`, `subprocess` and `scripts.metadata.errors` only) and move `StrictSafeLoader`
into `scripts/metadata/yaml_loader.py` (imports `yaml` and `yaml.constructor` only). `contract.py`
imports and re-exports all five names, so the existing contract tests and call sites keep working
unchanged. Do not add jsonschema to the generator: the generator reads metadata, it does not
validate it, and the review rejected that option.

**`preload_extra_configs` is new and must be specified, not guessed.** `check_architecture.py`
never needs the shared ini because every homework environment repeats `lib_deps`; `affected.py`
does need it for `framework` (RESEARCH Pitfall 8). The real shapes are
`extra_configs = ../../platformio.shared.ini` in `homeworks/1_3-police-flasher/platformio.ini:6`
and `extra_configs = ../platformio.shared.ini` in `tests/platformio.ini:6`, so every entry resolves
relative to the containing project directory (`Path(project_dir) / entry`), never to the repository
root. Semantics, fixed here so both callers agree:

- read the raw value, then cut it at the first `;` or `#` (an inline comment);
- split the remainder on commas, then on whitespace, dropping empty tokens;
- resolve each token against `project_dir` and call `parser.read()` on it;
- a token containing a quote character is a `CheckError` (PlatformIO does not quote these paths,
  and silently mis-resolving one is worse than refusing it);
- a named file that does not exist or cannot be read is a `CheckError` naming the entry and the
  project;
- return the resolved paths in entry order.

**`requirements-docs.txt` is Wave 0 infrastructure, not a docs-plan detail.** The pin file is the
single source the docs plan and `test_docs_pins.py` read, and `uv run --with-requirements
requirements-docs.txt mkdocs build --strict` is the documented local build command. Three exact
pins, no hashes (D-30). `pymdown-extensions` is pinned to the published artefact string `12.3`,
not the docstring's `12.3.0` (RESEARCH §Standard Stack).

**The fixture is the shared contract for four later plans.** `write_synthetic_root` must carry the
top-level `tests/` consumer (05-04's HIGH finding), a marker-bounded `docs/index.md` (05-07's
`ERROR`-on-missing behaviour), a `boards/` profile (05-07 board pages), and a `homeworks=False`
mode (05-05's zero-homework exit-2 case). It deliberately does not copy `partitions/`, the authored
`docs/decisions/` tree, the real `homeworks/` tree, or `lib/` via symlink; state that non-copy list
in the docstring, because `build_root` does copy `partitions/` at
`scripts/tests/temp_root.py:26-37` and the difference must be intentional rather than accidental.
