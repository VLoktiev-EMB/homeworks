**This plan changes no behaviour.** It is a pure extraction plus two new files. The gate for the
extraction commits is that the existing 81-test suite and `python3 scripts/check_architecture.py`
stay green with no assertion edited to accommodate the move.

**Why `errors.py` exists.** `scripts/metadata/contract.py` imports `yaml` and
`jsonschema` at module scope, and `scripts/tests/` may not import either library (04/D-14). If
`render.py` imported `CheckError` from `contract.py`, any test that imports the renderer would
transitively import PyYAML. Moving the one exception class to `scripts/metadata/errors.py` and
re-exporting it from `contract.py` keeps `from scripts.metadata.contract import CheckError`
working for every existing call site while letting `render.py` and `platformio.py` stay
stdlib-only. Do not create a second exception class and do not define one inside `render.py`.

**Why `platformio.py` is extracted, not copied.** `scripts/check_architecture.py` currently owns
its own `CheckError`, `resolve_root`, `_option`, `_extends_targets` and `_dep_names`, and it has no
`sys.path` bootstrap because it is run as a standalone script. Adding the bootstrap and importing
the shared module is the whole change; the local `resolve_root` may stay where it is. Keep the
function bodies byte-for-byte identical — including the `native` PREFIX rule at
`scripts/check_architecture.py:438-443` and the `name=symlink://` alias rule at lines 464-489 —
because both were review findings (03-REVIEW CR-01, WR-03) and the public names `option`,
`extends_targets`, `dep_names`, `load_ini` are what `scripts/affected.py` will import.

**`preload_extra_configs` is new.** `check_architecture.py` never needs the shared ini because
every homework environment repeats `lib_deps`; `affected.py` does need it for `framework`
(RESEARCH Pitfall 8). Add one helper that reads `[platformio] extra_configs`, resolves each entry
relative to the project directory, and calls `parser.read()` on it. It belongs in the shared
module so both callers agree on the resolution rule.

**`requirements-docs.txt` is Wave 0 infrastructure, not a docs-plan detail.** The pin file is the
single source the docs plan and `test_docs_pins.py` read, and `uv run --with-requirements
requirements-docs.txt mkdocs build --strict` is the documented local build command. Three exact
pins, no hashes (D-30). `pymdown-extensions` is pinned to the published artefact string `12.3`,
not the docstring's `12.3.0` (RESEARCH §Standard Stack).
