**Workspace formatting is a compatibility requirement, not a preference.** The current
`homeworks.code-workspace` is tab-indented, carries no `name` keys, and holds an `extensions` block
with one recommendation and two unwanted ones. Emit `{"name": …, "path": …}` pairs, keep the
`extensions` block verbatim inside the template, and build the folder fragment as
`\t\t{\n\t\t\t"name": <json string>,\n\t\t\t"path": <json string>\n\t\t},` lines joined with `\n`
(trailing comma between entries, none after the last). `json.dumps(value, ensure_ascii=False)` is
the only serializer for the two string values. A VS Code re-save must then be byte-identical, so
the first generation diff is only the folder list. The file is already exempt from `.gitignore`
through the `!*.code-workspace` negation.

**Display names, not paths.** The fixed roots use the names `repo`, `docs`, `lib`, `scripts`. A
homework folder's `name` is `<module>.<lesson> <title>` (for example `1.3 Police Flasher`) and its
`path` is `homeworks/<id>`. META-07 allows emoji in a display name; the path stays ASCII, and the
generator refuses a path that contains a non-ASCII byte rather than trusting the schema.

**The pin cycle (RESEARCH Pitfall 6).** `check_metadata.py` validates each `homework.yaml` pin
against `platformio.shared.ini`, while D-16 makes the ini a projection of the metadata. Collect
the distinct `(toolchain.platformio, toolchain.platform)` pairs across every homework document:
zero documents is exit 2 (there is nothing to derive the pins from); more than one distinct pair is
exit 1 with one record per disagreeing homework naming its pair. Never pick a winner.

**The template keeps the file's own words.** Copy `platformio.shared.ini` into
`templates/views/shared-ini.ini.tmpl` with only three edits: a generated-file header comment (which
also gives the PlatformIO Core pin a home it does not have today), `platform = {{platform_pin}}` in
both ESP sections, and `{{platformio_pin}}` inside that header. The five-line SCons comment above
`[native_unity]` survives verbatim, including the `Do not move it into a per-project override.`
line. Add no section and no homework id.

**Do not touch what the phase does not own.** This plan generates two files. It does not generate
`homeworks/<id>/.gitignore`, `homeworks/<id>/.vscode/*` or any other per-homework editor file
(D-25, F-05, F-18); those stay untracked IDE output.

<threat_model>

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `homework.yaml` values to the workspace JSON and the shared INI | A title or path becomes a JSON string or an INI value; a newline or quote could break either format. |
| `homework.yaml` pins to the shared configuration | Two homeworks may declare different pins, and the file the checker validates against is the one being written. |
| Template text to a whole-file write | A whole-file view has no marker protection, so the template is the only review surface. |

### STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-14 | Tampering | `workspace` folder fragment | high | mitigate | `json.dumps(value, ensure_ascii=False)` is the only serializer for the two string values, so a title containing a quote or newline cannot break the file; the path is additionally required to be ASCII with no `..` segment. |
| T-5-15 | Tampering | `shared-ini` pin substitution | high | mitigate | The pin vocabulary is two placeholders substituted through the closed `render()` map; `render()` raises on an unknown token or a `${...}` occurrence, so an unexpected template edit cannot silently pass through. |
| T-5-16 | Repudiation | `shared-ini` disagreement handling | high | mitigate | More than one distinct pin pair blocks the run with exit 1 and one record per homework; there is no tie-break, no default, and no partial write. |
| T-5-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing; it writes two text files from reviewed templates using the same `PyYAML==6.0.3` the generator already declares. |

</threat_model>
