**One view, three target families.** The `docs` subcommand owns `docs/index.md` as a `region`
target and `docs/homeworks/*.md` plus `docs/boards/*.md` as `whole` targets. This plan adds the
page families first and the home region last, so each task leaves `docs --check` green on the real
tree.

**The metadata card.** Fields, in this order: ID, Title, Board, Framework, Language, Status,
Toolchain, Simulation. Toolchain is `PlatformIO <toolchain.platformio> · <toolchain.platform>`
(for the real homework, `PlatformIO 6.2.0 · espressif32@8.0.0`). Simulation is
`<tool> (<status>)` when a `simulation` block exists and `none` when it does not; a `tool` of
`none` also renders `none`. Every value passes through `_escape_cell`.

**Links are absolute and built from `REPOSITORY_URL`.** `report_url` is
`<REPOSITORY_URL>/blob/main/homeworks/<id>/<report.path>` and `readme_url` is
`<REPOSITORY_URL>/blob/main/homeworks/<id>/README.md`. MkDocs treats a relative `.md` link as a
docs-relative target; `../../homeworks/<id>/report.md` does not exist under `docs/`, and
`--strict` turns that warning into a build failure (Pitfall 3). A `homeworks/<id>/README.md` link
must never be relative either, for the same reason.

**The home page reuses the README's template.** `docs/index.md` is authored prose plus the marker
region from `templates/views/homeworks-table.md.tmpl`, rendered with
`_homework_rows(..., link_style="absolute")`. D-11 says the table is identical in both places; using
one template is how that stays true. The authored prose is written once in this plan and is never
rewritten by the generator.

**Board pages are a projection of the profile.** Read `boards/*.yaml` with `yaml.safe_load`, render
`# <board-id>`, a two-column table of `SoC`, `Flash`, `PSRAM`, `Frameworks` and `Pinout`, then a
`## Homeworks on this board` list linking `../homeworks/<id>.md` for every homework whose `board`
equals the profile id, or the single line `_No homework uses this board yet._` when there are none.
A `../homeworks/<id>.md` link is legal and resolvable because both live under `docs/`; it is the
one relative link the generator may emit, and it must never point outside `docs/`.

**Owned directories and orphans.** `docs/homeworks/` and `docs/boards/` are fully owned. A `.md`
file there that is neither in the previous manifest nor produced by the current run is an `ORPHAN`.
This is the only view with a directory scan; do not extend the scan to `docs/decisions/`, which is
authored.

**Do not touch `docs/decisions/`.** Its twelve files, including the `README.md` that becomes the
`decisions/` index, are authored and stay byte-identical.

<threat_model>

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `homework.yaml` and `boards/*.yaml` to published Markdown | Titles, board values and URLs become rendered cells on a public site. |
| Generated page paths to the filesystem | A page path is derived from an id or a file stem; a crafted id could escape `docs/`. |
| The owned page directories to deletion | `docs/homeworks/` and `docs/boards/` are scanned for orphans. |

### STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-19 | Tampering | Page templates and `_escape_cell` | high | mitigate | Every metadata value passes through `_escape_cell` (control characters and newlines collapsed, `\|` escaped); no value is emitted as raw HTML; a title that escapes to empty is refused. |
| T-5-20 | Tampering | Page target paths | high | mitigate | Page paths are `docs/homeworks/` plus a schema-constrained id, or `docs/boards/` plus a file stem matched against an anchored pattern; the `lstat` component walk runs before any write, and `_allowed_target` rejects anything outside the static allowlist. |
| T-5-21 | Repudiation | Orphan scan over the page directories | high | mitigate | An orphan is reported with exit 1; write mode removes it only when the previous manifest listed it and it carries the generated header, so an authored file dropped into `docs/homeworks/` is never silently deleted without first failing the check. |
| T-5-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs nothing; the generator reads YAML with the already-pinned `PyYAML==6.0.3`. |

</threat_model>
