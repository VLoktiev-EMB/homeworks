**Copy the schema envelope, not the schema body.** `schema/homework.schema.json` sets
`"$schema": "https://json-schema.org/draft/2020-12/schema"`, `"additionalProperties": false`, an
explicit `required` array, and anchored `pattern` shapes. The board profile is flat — six scalar
fields and one array — so it needs no `$defs`, but it keeps the same strictness. `pinout_url` uses
the pattern `^https://[^\s]+$`, never `"format": "uri"`, because a `format` keyword is accepted
without a checker (the reason is already written in
`test_homework_metadata.SchemaShapeTest.test_schema_contains_no_format_keyword`).

**The `frameworks` array is an enum, not free text.** `{"type": "array", "uniqueItems": true,
"items": {"enum": ["arduino", "espidf"]}}` — the same two values `homework.schema.json` allows for
a homework's `framework`, so a board can never advertise a framework no homework can declare.
Write that rationale into the schema's `description` field rather than leaving the enum unexplained.

**Parse with the repository's strict loader.** `scripts/metadata/contract.py:73-101` already
defines `StrictSafeLoader` because PyYAML silently keeps the last value of a duplicated mapping
key. Board documents are authored data and `psram`, `pinout_url` or `frameworks` can be duplicated
by a bad merge, so `validate_board_text` must call `yaml.load(text, Loader=StrictSafeLoader)` and
must not call `yaml.safe_load`. Import the loader from `scripts.metadata.yaml_loader` (created in
05-01) so this module does not depend on the re-export ordering in `contract.py`.

**A symlinked board document is refused.** The homework checker resolves identity lexically and
never follows a symlink; `_board_documents` matches that posture. If `boards/<stem>.yaml` is a
symlink, emit one `ERROR` record naming the relative path and do not read it. A directory symlink
for `boards/` itself is also an `ERROR` (the walk must not leave the repository).

**Positional arguments are routed per family (review finding 7).** `_directories` currently treats
any file argument as a child of a homework directory (`scripts/check_metadata.py:153-174`), so
`boards/esp32-s3-devkitc-1.yaml` becomes `boards/` and produces "directory contains neither
homework.yaml nor task.md". Change `main`: partition `args.paths` into board paths and homework
paths; a path is a board path when it resolves under `<root>/boards/` and names a `.yaml` file,
otherwise it is a homework path. Call `_board_documents(root, board_paths)` and
`_directories(root, homework_paths)` with the partition. When `args.paths` is non-empty, a family
with no selected paths is scanned not at all — it must never fall back to "all", which would make
a board-only invocation validate every homework and vice versa. When `args.paths` is empty, both
families scan everything, preserving today's behaviour.

**Identity is lexical, like `homework.yaml`.** The file stem must equal the document's `id`. Mirror
`scripts/metadata/contract.py`'s `_homework_directory` identity rule: compare the two strings,
never resolve either through the filesystem, and report the mismatch as an `ERROR` record
(exit 1), not a `CheckError`.

**Do not add a cross-existence rule.** It is tempting to fail a `homework.yaml` whose `board` has no
profile. Do not: it would invalidate every existing fixture root in `test_homework_metadata.py` and
it is not what D-27 asks for. The homework page shows the board id as text; the Boards nav lists
whichever profiles exist.

**A missing `boards/` directory is not an error.** `_directories` already tolerates a missing
`homeworks/`; `_board_documents` must behave the same way so the metadata fixtures, which copy only
`schema/` and `platformio.shared.ini`, stay green with no edit.
