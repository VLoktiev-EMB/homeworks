**Copy the verified skeleton; do not improvise it.** RESEARCH §Code Examples carries a complete
`mkdocs.yml` that returned exit 0 against this repository's real `docs/` tree. Reproduce it in
`templates/views/mkdocs.yml.tmpl` field for field: `site_name`, `site_url`, the Material theme with
`features` (`navigation.sections`, `navigation.top`, `content.code.copy`) and the two light/dark
palette entries, `plugins: [search]`, the `validation:` block (`nav.omitted_files: warn`,
`nav.absolute_links: warn`, `links.not_found: warn`, `links.absolute_links: warn`,
`links.unrecognized_links: warn`, `links.anchors: warn`), the full `markdown_extensions` list
including `pymdownx.arithmatex` with `generic: true`, and the three `extra_javascript` entries in
the order `katex.min.js`, `contrib/auto-render.min.js`, `render-math.js`, after the single
`extra_css` entry.

**Nav entry syntax (Pitfall 1).** `- "Title": path` with the separator colon unquoted. Do not quote
the whole entry, do not use a YAML block scalar, and do not emit a bare `- path` for a titled
entry. The generated entries are indented four spaces under their section key; the Decisions
children are indented six.

**Pitfall 2 is why the Decisions section is generated from a directory scan.** With
`nav.omitted_files: warn`, `--strict` fails if any Markdown file under `docs/` is absent from
`nav:`. The twelve authored files in `docs/decisions/` are exactly what a hand-written nav forgets,
so scan `docs/decisions/*.md`, list `README.md` first as `Decision record index`, then the rest
sorted by filename, each labelled from its first ATX heading.

**`site_url` must be the project URL, not the apex.** GitHub Pages lower-cases the owner:
`https://vloktiev-emb.github.io/homeworks/`. Leave `docs_dir` and `site_dir` at their defaults
(`docs`, `site`), so the build writes only into the gitignored `site/` directory.

**Building is not a generator concern.** `scripts/gen_views.py` never invokes MkDocs; the build is a
separate command the developer and CI run. Keep generation deterministic: no clock, no network, no
subprocess.

**Do not add anything the Zensical constraint forbids.** No plugin beyond `search`, no `hooks:`
block, no `custom_dir` (D-08 forbids `docs/overrides/`), no `INHERIT:` base file.
</context>

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authored ADR headings to YAML nav labels | An ADR heading is free text inside a quoted YAML scalar. |
| `requirements-docs.txt` and the vendored tree to the site build | A pin that disagrees with the vendored version produces a site that silently fails to render math. |
| Generated config to the published site | The configuration decides which local files the published bundle serves. |
