**Input.** Three sources, in precedence order: `--paths-from PATH` reads a file (NUL-separated when
it contains a NUL byte, otherwise newline-separated, trimmed, empties dropped) and never touches
git; `--base REV` runs `git diff --name-only -z <REV>...HEAD`; neither runs
`git diff --name-only -z HEAD` (working tree versus `HEAD`). Use `-z` so a path containing a space
survives, decode with `errors="surrogateescape"` so a non-UTF-8 path cannot abort the run, and pass
every path through the same containment test `check_architecture._read_sources` uses: reject an
absolute path, a Windows-absolute path, or any `..` segment, and treat it as an unrecognised
shared path (fail-safe widen) rather than reading it.

**Fanout table (D-24, with the adopted reading of RESEARCH Open Question 1).**

| Changed path | Effect |
|---|---|
| `<prefix>` in `NO_BUILD_IMPACT` = `.planning/`, `docs/`, `.github/`, `templates/views/`, `boards/`, or exactly `README.md`, `AGENTS.md`, `LICENSE`, `generated.manifest`, `mkdocs.yml`, `requirements-docs.txt`, `homeworks.code-workspace` | empty `build` and `simulate` |
| `homeworks/<id>/…` | that project's environments |
| `lib/<name>/…` | every project whose `lib_deps` names `<name>`, transitively through `lib/<name>/library.json` `dependencies` |
| exactly `platformio.shared.ini`, or `partitions/…`, `scripts/pio/…`, `schema/…`, `scripts/affected.py` | every project |
| anything else | every project (fail-safe) |

The `generated.manifest`, `mkdocs.yml`, `requirements-docs.txt`, `homeworks.code-workspace`,
`templates/views/` and `boards/` entries are the review's over-approximation fix: without them every
pull request that regenerates a view — which always rewrites `generated.manifest` — would widen to
every project and rebuild the whole tree. They are documentation and view inputs, not compilation
inputs, so they belong in the no-build-impact set. Do not add `.planning/` back to the widen set and
do not drop the fail-safe: an unknown path still widens.

**The project set includes the top-level `tests/` project (review finding 5).**
`tests/platformio.ini:25-29` consumes `common`, `port` and `host`, so it is a real consumer of the
shared libraries. `_projects` must return one record for every `homeworks/*/` directory **and** one
for the top-level `tests/` directory when `tests/platformio.ini` exists, with `project: "tests"`.
`tests` has no `homework.yaml`, so its `simulation.tool` is `none` and it contributes to `build`
only. Its `native` environment is also excluded from `simulate` by the native rule, so the two
reasons agree and the test asserts both.

A `library.json` with no `dependencies` key is a leaf; every real manifest carries only `name`,
`version` and `build` today (RESEARCH Pitfall 9), and every current project lists `port` directly,
so the one real edge is already covered. Do not invent a registry-shaped dependency and do not add
a `homework.yaml` field. Walk the `library.json` `dependencies` edges with a `seen` set so a
malformed cycle terminates.

**Read metadata with the strict loader.** `simulation.tool` comes from `homework.yaml`; parse it
with `StrictSafeLoader` from `scripts.metadata.yaml_loader`, not `yaml.safe_load`, so a duplicated
`simulation` key is a `CheckError` rather than a silently chosen value.

**Environments and framework.** For each project INI, build the parser with `load_ini`, call
`preload_extra_configs(parser, project_dir, display)` so `[platformio] extra_configs` is read
before `extends` is walked, then enumerate every `[env:<name>]` section. `framework` is
`option(parser, section, "framework")`. The shared `[native_unity]` section declares
`platform = native` but no `framework`, so when `framework` is unset and the resolved `platform`
is `native`, report `framework: "native"`; when a non-native environment has no resolvable
`framework`, that is a `CheckError` (exit 2) rather than an empty string. Both lists carry the same
entry shape. `simulate` drops native environments and drops a project whose `homework.yaml` has
`simulation.tool` equal to `none` or no `simulation` block.

**Output.** Default `--format json` prints
`json.dumps({"build": [...], "simulate": [...]}, indent=2)` plus one newline, with each list
sorted by `(project, env)`. `--format paths` prints `build <project> <env> <framework>` and
`simulate <project> <env> <framework>` lines, `build` block first. Every diagnostic goes to
stderr; stdout carries the payload and nothing else, because Phase 8 pipes it into
`fromJson(...)`.

**Exit codes.** 0 success; 1 a content problem — a diff under `homeworks/<id>/` where the directory
contains `homework.yaml` or any source file but has no `platformio.ini`, reported on stderr with a
message that says to add the file or move the change; a completely empty homework directory is
skipped, because a metadata-only or still-scaffolding directory is not a matrix correctness
problem. Exit 2 is a usage or environment error (bad arguments, an unreadable `--paths-from` file,
a failing `git diff`, an unreadable INI or metadata document).

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Git diff output to the mapper | Path names are contributor-controlled and may be absolute, contain `..`, hold embedded NULs or be non-UTF-8. |
| `platformio.ini` and `library.json` to the dependency graph | A missing or malformed dependency edge silently changes which projects are built. |
| stdout to the Phase 8 workflow | The JSON is piped into `fromJson(...)`; any stray text breaks the matrix. |

### STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-5-11 | Tampering | `_changed_paths` | high | mitigate | `-z` parsing, `surrogateescape` decoding, and a containment test that rejects absolute, Windows-absolute and `..`-bearing paths; a rejected path widens the set instead of being read or echoed. |
| T-5-12 | Repudiation | `_fan_out` fail-safe | high | mitigate | The `NO_BUILD_IMPACT` set is explicit, documented in the module docstring and tested entry by entry; everything else widens to every project, so an unknown shared input can never skip a build. |
| T-5-13 | Tampering | `_consumers` | medium | mitigate | The graph is derived only from `lib_deps` plus `library.json`, read through the module extracted in 05-01; the `name=` alias is ignored in favour of the `symlink://` spec, `native` is matched as a prefix, and a `seen` set bounds the transitive walk. |
| T-5-32 | Repudiation | `_projects` project set and `NO_BUILD_IMPACT` | high | mitigate | The project set includes the top-level `tests/` consumer, so a `lib/**` change cannot skip the shared native suite; `NO_BUILD_IMPACT` names every view input explicitly so a docs-only pull request does not rebuild the tree, while any unrecognised path still widens. Both directions are tested entry by entry. |
| T-5-SC | Tampering | npm/pip/cargo installs | high | mitigate | The mapper's PEP 723 header adds only `PyYAML==6.0.3`. The tests invoke `uv run` on the same script; no new package enters the graph. |

</threat_model>
