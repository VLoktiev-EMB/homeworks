## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem -> checker | `homework.yaml` under `homeworks/` is untrusted input parsed by PyYAML |
| schema file -> validator | a malformed or over-permissive schema silently weakens every check |
| checker -> CI | exit codes and `--json` records are consumed by Phase 8 automation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of Service | `validate_homework_text` | medium | mitigate | `StrictSafeLoader` (a `SafeLoader` subclass, so no arbitrary object construction) and a 64 KiB `MAX_INPUT_BYTES` cap before parsing; an oversized or malformed input is an ERROR record and exit 1 because it is a violation of a file under `homeworks/`, not an environment failure |
| T-04-04 | Tampering | `schema/homework.schema.json` | high | mitigate | Every shape is an anchored `pattern`; the suite asserts the schema contains no `format` keyword (Pitfall P1 proved `format: uri` accepts `not a url`) |
| T-04-20 | Tampering | duplicate YAML mapping keys | medium | mitigate | `StrictSafeLoader.construct_mapping` rejects a repeated key and names it, so a duplicated `source:` or `toolchain:` block cannot silently override the first value; a duplicate-key fixture asserts exit 1 |
| T-04-07 | Repudiation | checker output | medium | mitigate | Sorted paths, no timestamps, no writes; a test compares two consecutive runs byte-for-byte and asserts `git status --porcelain` is unchanged |
| T-04-08 | Information Disclosure | record rendering | low | mitigate | Print repository-relative POSIX paths only; never echo an absolute root or a configured identity |
| T-04-SC | Tampering | package installs (`uv`, pre-commit) | high | mitigate | Blocking human-verify gate (Task 1) before the first install; versions pinned to PyYAML 6.0.3 and jsonschema 4.26.0 in the PEP 723 header, and the drift test in 04-04 keeps the pre-commit declaration equal |
</threat_model>
