<objective>
Attempt the Velxio self-host image as the role-proportional second measurement: boot, image identity, board coverage, and an honest statement of whether the pilot can compile or run there.

Purpose: The phase needs a measured comparison beyond Wokwi without spending Wokwi quota. Velxio's prebuilt container is the cheapest second real measurement (D-05), and its self-host board limit is itself evidence. The attempt is owner-run because the command sandbox cannot reach the Docker socket (D-06).

Output: the `## Velxio self-host attempt` section of `07-SPIKE-EVIDENCE.md`, with a digest or a named pull failure, a boot measurement or a named failure, a substantiated board-coverage row, and the AGPL boundary.

Tracer note: this plan has no agent-runnable tracer. Every layer it touches — the Docker daemon, the registry, the container's editor and the owner's network — is outside the command sandbox, so the boot attempt itself is the thinnest end-to-end slice and is the first task. The agent's half is the recording task that follows.

Review-driven hardening (Round 1): a named board-capture protocol, a branch-aware evidence gate that distinguishes "no digest because the pull never happened" from a missing record, a bounded first-HTTP-200 boot definition, container cleanup, and a relaxed working-tree assertion.
</objective>

  <instructions>
    The agent presents the Velxio protocol block from `07-SPIKE-EVIDENCE.md` verbatim. The owner runs, in order: `docker rm -f velxio` if a container of that name already exists (cleanup only; never a different image tag, engine or port); `docker pull ghcr.io/davidmonterocrespo24/velxio:master`; `docker inspect --format '{{index .RepoDigests 0}}' ghcr.io/davidmonterocrespo24/velxio:master`; `time docker run -d --name velxio -p 3080:80 -v velxio-data:/app/data -v velxio-arduino-libs:/root/.arduino15 -v velxio-arduino-user-libs:/root/Arduino -v velxio-ccache:/var/cache/ccache -v velxio-build:/var/lib/velxio-build ghcr.io/davidmonterocrespo24/velxio:master`; then a bounded readiness poll of at most 60 attempts two seconds apart, each running `curl -sf -o /dev/null http://localhost:3080` and stopping at the first success; then `docker logs --tail 50 velxio`.

    Define boot readiness explicitly in the record: the measured interval is from the start of the `docker run` command to the first HTTP 200. Record the `docker run` wall time from `time` and the first successful poll time separately; the difference is not the boot interval and must not be reported as one. If 60 attempts pass without a 200, stop polling and record `not measured — no HTTP 200 within 120 s`; do not poll indefinitely.

    While the container answers, the owner opens `http://localhost:3080` and captures the board list by one of these named means, recorded verbatim in the paste-back: a screenshot saved outside the repository (for example `$HOME/velxio-boards.png`), the copied UI text of the board selector, or the page URL plus the exact reason the list could not be read. "The board list looked as expected" is not a capture.

    The owner pastes back: the pull result; the `RepoDigests` line; the `docker run` output with its wall clock; the first successful poll time or the 120 s timeout; the board capture or its exact unavailability reason; the last 50 log lines. If the daemon is unreachable, the pull fails, or the container never answers, the owner pastes the exact error text and stops. After capture, the owner runs `docker rm -f velxio`; the five named volumes intentionally persist and are not removed.

    The agent records the digest verbatim when the pull happened, the `docker run` wall time and the first-HTTP-200 time as separate `measured` values, the container name `velxio`, the five named volumes, the board capture reference, and the poll result. If the attempt failed, record `not measured — <exact reason>` with no inferred number (D-06). Never present the mutable `:master` tag as the identity.
  </instructions>
  <verification>The evidence file records a `@sha256:` digest, a `measured` `docker run` wall time and a `measured` first-HTTP-200 time, or a `not measured` row with the exact failure text; the board coverage rows carry either a named capture or an exact unavailability reason; the container name, the five volumes and the cleanup are recorded; the tag is never the recorded identity.</verification>
