<objective>
Close G-09-2 / truth 19 (review CR-01): `find_credential` must refuse a credential written as a
space-separated compound keyword, so `SECRET KEY: hunter2` from firmware can never reach
`.skill-state/logs/<id>.log`.

Verified failure: `find_credential(b"SECRET KEY: hunter2")` and
`find_credential(b"secret key = hunter2")` both return False today. `_KEYWORDS` admits
`api[ _-]?key` as a compound but has a bare `secret` alternative, and the assignment branch's
connector `[\w.-]{0,128}` cannot span a space, so neither branch reaches the separator. The
shared guardrails name a "secret … assignment" as refused, so the policy and the scan disagree.

Purpose: make the scan admit the shape the policy already names, without letting any pinned
benign negative start matching.
Output: the widened alternation, the documented shape, the fixture pins and an end-to-end
refusal test.

Design choice: widen the keyword alternation to `secret(?:[ _-]?key)?`, mirroring the existing
`api[ _-]?key` compound. A literal space, underscore or hyphen is admitted deliberately; a
whitespace class is not, because it would let a compound keyword span a line break in a device
log. The connector stays whitespace-free and the copula branch is unchanged, so
`auth mode = WPA2` and `secret is` remain unmatched. D-23's exit vocabulary is untouched: a
match is still `capture unavailable` with exit 1.
</objective>
