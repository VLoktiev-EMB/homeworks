<objective>
Close the two BLOCKER gaps that remain after plan 09-09, without reopening the baud work it
already closed:

- **GAP 1 / CR-01 — the capture cannot run at all.** The only executable example pipes the
  monitor's stdout, and PlatformIO 6.2.0 refuses a non-TTY stdout, so every run reports
  `capture unavailable` and no log is ever written. The fix is a real, tested helper,
  `scripts/serial_capture.py`, that allocates a pseudo-terminal for the child, puts the
  slave in raw mode, reads the master for a bounded interval, and never relies on a pipe.
  This is also the only way to satisfy the verifier's second required property: a
  deterministic check must exercise the capture path with a fake serial source.

- **GAP 2 / CR-02 — the credential gate is too narrow.** The regex requires an unquoted,
  unspaced separator and misses the ordinary forms the guardrails name. The helper owns one
  widened scan and one test suite that pins every shape the review executed.

Design choices and why:

- **A helper script, not a longer snippet.** A prose snippet cannot be executed by the
  suite; the verifier explicitly requires a deterministic check. The helper is stdlib-only
  (no pyserial, no new dependency), so the capture tests run in the same stdlib-only suite
  as every other checker.
- **A PTY around `pio device monitor`, not a direct serial read.** PlatformIO's own error
  recommends reading the device directly, but the announced command must stay the
  documented monitor command, and the PTY path keeps PlatformIO's port selection and
  `monitor_speed` inheritance. The helper runs the monitor with `--raw --quiet` and
  `-e env` only when the environment rule requires it.
- **The space-separated form is fail-closed at six characters.** The review's fixture is
  `password abc123` (six characters). A six-character floor catches that fixture and
  keeps ordinary words such as `secret is` out of the match. Occasional false positives are
  accepted: on a match the guardrails already require writing nothing and reporting
  `capture unavailable`.
- **Version stays `"0.1"`.** D-16 locks the version and the phase success criterion names
  0.1; the changelog records the behaviour change without a bump. D-20's scope is unchanged:
  confirmation, upload, bounded capture, no log interpretation.
- **Editing `scripts/affected.py` is itself in `WIDEN_ALL`,** so this pull request rebuilds
  every project once. That is the documented consequence of changing the mapper, not a
  reason to leave the new helper outside the no-build-impact policy.

Purpose: make the shipped capture both runnable and safe, and leave a test that fails if a
pipe-based capture or the narrow scan ever returns.
Output: a tested capture helper, a rewritten `hw-flash` contract, a restored shared secrets
rule, a corrected `AGENTS.md` paragraph, the regenerated mirror and manifest, and updated
review dispositions.
</objective>
