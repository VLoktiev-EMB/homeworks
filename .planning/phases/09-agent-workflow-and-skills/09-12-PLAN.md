<objective>
Close GAP 2 / WR-12: the credential scan must cover the ordinary password assignment forms
the shared guardrails already promise.

The shipped regex returns False for `password is hunter2`, `userpassword = hunter2`,
`passphrase = hunter2` and `pwd = hunter2`. Three independent causes: the leading
`(?<![a-z0-9])` lookbehind rejects a keyword preceded by a letter, `passphrase` and `pwd` are
absent from `_KEYWORDS`, and the space-separated branch demands six non-space characters
immediately after the whitespace, so the two-character copula `is` fails first. Under the sole
permitted capture write, those bytes would be persisted.

Purpose: make the implementation match the policy sentence, with an explicit rule for the
miss-versus-false-positive trade and a pinned benign-negative set.
Output: a widened scan, four new review shapes, explicit negative cases, the widened guardrails
sentence, the regenerated mirror, and the recorded disposition.

Design choice: drop the lookbehind entirely rather than adding a narrower embedded-keyword
pattern. A false match writes nothing and reports `capture unavailable`, so the fail-closed
direction is to catch more; the negative tests bound the regression to a benign boot log that
must never match.
</objective>
