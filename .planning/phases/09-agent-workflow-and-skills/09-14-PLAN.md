<objective>
Close the last failed must-have of Phase 9: truth 19 / RR-CR-01, "no skill writes a credential to
a log; the shared guardrails' secrets rule holds across every implemented skill."

The shipped `CREDENTIAL` regex (lines 99-103) requires the assignment separator immediately after
the keyword, so an identifier that continues past the keyword misses: `{"secretKey": "hunter2"}`,
`secret_key = hunter2`, `passwordHash: abcdef` and `SECRET_KEY = hunter2` all return False today.
`capture_and_store` scans and then writes, so those bytes would be persisted to
`.skill-state/logs/<id>.log` under the only permitted capture exception — violating the
guardrails `[MUST]` rule and the exception's own precondition.

Purpose: make the fail-closed scan cover keyword-prefixed identifiers, and make the policy, the
docstring, the tests and the records say exactly what the implementation does.
Output: the connector fix, an end-to-end refusal test plus the four unit fixtures, the widened
policy sentence, the regenerated mirror, and the reconciled review and security records.

Design choice: a `[\w.-]{0,32}` connector before the separator in the assignment branch only
(the shape the reviewer validated). The space-separated/copula branch and its six-character floor
stay byte-for-byte unchanged, so `secret is` and the other pinned negatives cannot start matching.
</objective>
