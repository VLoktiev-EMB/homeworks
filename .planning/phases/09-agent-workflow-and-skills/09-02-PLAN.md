## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| skill prose → agent runtime | User-facing policy text is interpreted by a model; a permissive sentence becomes a permission |
| canonical stub → mirror | A stub whose marker is lost would advertise an unimplemented capability |
| guardrails → every implemented skill | The policy is shared, so one edit changes every workflow |

## STRIDE Threat Register

`T-09-SC` is the reserved phase-level supply-chain row: it is the same phase-wide entry carried by every plan in Phase 9, not a plan-scoped threat, and is therefore exempt from the intra-phase `T-09-NN` uniqueness numbering.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-05 | Elevation | `guardrails.md` flashing section | high | mitigate | Require a literal affirmative, forbid a default yes, forbid pre-approving `upload` in `allowed-tools`, and treat any other answer as a stop. |
| T-09-11 | Spoofing / Transparency | the four stub skills | high | mitigate | Every stub carries `metadata.status: stub` plus a body banner naming the missing capability and the manual fallback; a promoted skill removes both in the same change. |
