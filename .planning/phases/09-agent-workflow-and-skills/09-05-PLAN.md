<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → hardware | An upload changes a physical device; consent must come from the human |
| serial stream → log file | Device output is untrusted and may contain anything, including secrets |
| user answer → gate | A conditional or ambiguous answer must not be read as consent |
| device path → capture process | The capture runs a real program with access to a serial port |

## STRIDE Threat Register

`T-09-SC` is the reserved phase-level supply-chain row: it is the same phase-wide entry carried by every plan in Phase 9, not a plan-scoped threat, and is therefore exempt from the intra-phase `T-09-NN` uniqueness numbering.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-21 | Elevation | the consent gate before `-t upload` | high | mitigate | Print board, environment and command; accept only the literal `так` or `yes`; every other answer stops; never pre-approve `upload` in `allowed-tools`; never reuse a confirmation. |
| T-09-22 | Information disclosure | `.skill-state/logs/<id>.log` and the transcript | high | mitigate | The log lives under the ignored `.skill-state/`; the skill never echoes a token; no log content is quoted into a report or commit. |
| T-09-23 | Tampering / Elevation | homework id in the upload and monitor commands | medium | mitigate | Validate the id against the canonical pattern and pass it as one argv element. |
