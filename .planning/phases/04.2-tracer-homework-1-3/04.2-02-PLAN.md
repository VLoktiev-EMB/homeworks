**Library mechanism (verified):** a project-local library under
`homeworks/1_3-police-flasher/lib/pattern/` is auto-discovered by both environments. The
manifest must omit `frameworks` and `platforms`; declaring `"frameworks": ["arduino"]` makes
the library invisible to `[env:native]` with `'pattern/pattern.h' file not found` (RESEARCH
Pitfall 2). Do not add a `lib_deps` entry and do not set `test_build_src`.

**Canonical wiring (matches D-03 and the report):** the default profile is
`PATTERN_GPIO_SINGLE`. GPIO4 drives the half-bridge pair through one 150 ohm resistor: LED1
anode at node X and cathode at GND lights on HIGH; LED2 anode at 3V3 and cathode at X lights on
LOW. GPIO6 drives the third LED through its own 150 ohm resistor. GPIO7 reads the button with
`PORT_GPIO_INPUT_PULLUP`. GPIO5 exists only for the alternative `PATTERN_GPIO_THREE_LEDS`
profile. This pin map must match plan 03's `assets/diagram.json` and plan 04's report.

**Test doubles:** `host_fake_gpio_reset` zeroes every level, so an idle `INPUT_PULLUP` button
reads LOW by default. Set `fake.level[BUTTON_PIN] = PORT_GPIO_HIGH` in `setUp()` before the
first tick, and call both `host_fake_gpio_reset` and `host_fake_time_reset` in every `setUp()`
so the injected-failure flag and write counters cannot leak between cases (RESEARCH Pitfall 9).
`host_fake_time_advance` mutates the caller-owned struct, so a port obtained earlier observes
the new time.

**Library ordering is implicit.** `lib/pattern/library.json` declares no dependencies; it
resolves `common` and `port` because the homework's `lib_deps` lists them and project-local
`lib/` is discovered first. This works today but a later "cleanup" of `lib_deps` would break it
silently, so the friction log must record the coupling.

**The architecture checker does not see homework includes.** `scripts/check_architecture.py`
classifies `homeworks/**` as owner `homeworks` and skips the external-header allowlist for that
owner, so "no framework header in `lib/pattern`" needs its own include scan in the verify.

**Half-bridge fidelity:** `PORT_GPIO_INPUT` is a high-impedance input, not a driven LOW. The
off state is dark only as a simulation approximation; on hardware the shared node floats near
the LED clamp voltage and may leave a faint glow. `PATTERN_MODE_SOLID` on one pin drives HIGH
(`led_a` wins), so the LOW-lit LED of the pair stays dark. Both facts are limitations, not
bugs, and both propagate to plan 04 and plan 05.

**No new packages:** the library compiles from the repository's own headers; the native suite
already fetches Unity 2.6.1.
