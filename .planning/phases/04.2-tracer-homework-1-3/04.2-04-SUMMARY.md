## Accomplishments

- Created `report.md` with the fixed heading contract: `## 1. Title and Metadata` through
  `## 10. References`, then `## Decision Appendix`. The metadata table records the homework id,
  board, framework, PlatformIO 6.2.0, `espressif32` 8.0.0, the `in-progress` status, report
  status `draft`, and implementation commit `6a60426` in an `Implementation commit` row.
- Derived the BOM and pin map from `assets/diagram.json`: seven part rows keyed by the diagram
  ids (`esp`, `r1`, `led1`, `led2`, `r2`, `led3`, `btn1`), and every required net from GPIO4,
  GPIO5 (reserved), GPIO6, GPIO7, `3V3.1`, and `GND.1` to `GND.3`.
- Wrote six calculations (C-01..C-06) for the series resistor, LED current, resistor power,
  off-state reverse voltage, pattern period, and GPIO margin. Each row prints its formula,
  units, input provenance, result, uncertainty, and assumption effect; the inputs are
  `datasheet` or `calculated`, and bench inputs are `pending measurement`.
- Stated both half-bridge limitations: the all-off frame leaves node X at high impedance, so
  "both LEDs dark" is a simulation approximation and the off LED's reverse voltage is not
  well-defined; SOLID on one pin lights only the HIGH-side LED of the pair.
- Wrote a four-item safety checklist specific to this wiring: the direct 3V3-to-node-X short
  risk, the 150 ohm per-pin current limit against the 40 mA absolute maximum, LED polarity, and
  the shared ground.
- Cited the ESP32-S3 datasheet [1], the DevKitC-1 user guide [2], the PlatformIO unit-testing
  documentation [3], and the Wokwi diagram-format documentation [4] in the body, leaving the
  IEEE reference list itself to plan 05 as the plan's context requires.
- Logged friction F-11: the bare report template, the section contract spread across
  REPORT-01..08, the heading-numbering decision, and the need for a provenance vocabulary
  before any measurement existed.

## Decisions Made

- **Headings are numbered from title and metadata.** REPORT-01 places title and metadata first,
  so objective is section 2, theory 4, hardware 5, methodology 6, results 7, analysis 8,
  conclusions 9, and references 10. Plan 05 asserts the same literal text.
- **The implementation commit is `6a60426`.** It is the tree at the start of this plan and the
  code the report describes. Plan 05 must use the same hash in every ledger row or refresh
  both records in one commit.
- **BOM refs are the diagram part ids.** Using the same identifiers as `assets/diagram.json`
  removes a second naming scheme and makes the part-to-row trace mechanical.
- **The floating node is excluded from the reverse-voltage calculation.** The all-off frame
  sets GPIO4 to `INPUT`, so node X floats; the calculation applies only while the opposite LED
  conducts and clamps the node.
- **The reference list waits for plan 05.** The plan reserves sections 7-10, so the body cites
  [1]-[4] now and the IEEE entries arrive with the analysis that uses them. This keeps the
  pending contract intact and leaves no citation orphaned.
