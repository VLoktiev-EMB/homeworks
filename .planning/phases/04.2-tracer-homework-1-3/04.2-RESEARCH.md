## Summary

The phase is mechanically feasible, but three things in the current repository and toolchain will bite if planned literally.

First, **D-08's `retrieved: 2026-10-23` does not pass the metadata checker**. `valid_iso8601` requires a timezone (`scripts/metadata/contract.py:138-144`), and the repository's own test names the bare date as a rejected case (`scripts/tests/test_homework_metadata.py:339-343`). The same frontmatter with `2026-10-23T00:00:00Z` passes. The plan must flip `status` to `in-progress` and the timestamp in the same commit, or the pre-commit `check-metadata` hook blocks the change.

Second, **D-06 is confirmed, with one condition**: a private `lib/pattern/` with `library.json` is discovered automatically by both `[env:esp32s3_arduino]` and `[env:native]` with `test_build_src = false`, no `lib_deps` entry, and `#include <pattern/...>`. But declaring `"frameworks": ["arduino"]` in `library.json` makes the library invisible to the native environment in the default `soft` compatibility mode — verified by a probe that failed with `'pattern/pattern.h' file not found`. Omit `frameworks` and `platforms`, exactly as the five existing shared libraries do.

Third, **Wokwi is blocked twice**: `wokwi-cli` requires `WOKWI_CLI_TOKEN`, which is not set here, and the canonical Wokwi merge script does not run on the pinned `espressif32@8.0.0` because the platform renamed `tool-esptoolpy` to `tool-esptool` and esptool 5 hyphenated its subcommands (`merge-bin`, `--flash-mode`, `--flash-size`). A corrected script was verified to produce `firmware.merged.bin` from the custom 16 MB partition table. `wokwi-cli lint --offline assets/diagram.json` works without a token and is the honest local validation for this phase.

**Primary recommendation:** scaffold with `uv run scripts/new_homework 1_3-police-flasher --template arduino`; add `lib/pattern` with `name`/`version`/`build.srcDir`/`build.includeDir` only; keep the controller behind `port_gpio_t`/`port_time_t`; use GPIO 4/5/6 for outputs and GPIO 7 for the button; wire the single-GPIO pair as a half-bridge (LED1 to GND, LED2 to 3V3, one 150 Ω resistor from the GPIO to their common node); correct the provenance timestamp; and either adopt the adapted merge script or point `wokwi.toml` at `firmware.bin` and record the limitation.

### Pattern 1: Homework-local private library (D-06)

**What:** place the pure logic in `homeworks/<id>/lib/pattern/` with a `library.json`; PlatformIO's Library Dependency Finder scans the project `lib_dir` first and builds the library for both the firmware and the test environment.
**When to use:** any homework whose logic must be unit-tested natively without `test_build_src`.
**Example (verified):**

```json
{
  "name": "pattern",
  "version": "0.1.0",
  "build": {
    "srcDir": "src",
    "includeDir": "include"
  }
}
```

```c
/* test/test_pattern/test_pattern.c */
#include <unity.h>
#include <pattern/pattern.h>
```

The probe compiled `liba0b/pattern/pattern.c.o` into the Arduino target and `libf25/pattern/pattern.o` into the native test binary with no `lib_deps` entry and `test_build_src = false`.

### Pattern 2: Controller behind the consumer-owned ports (D-07)

**What:** the controller takes `port_gpio_t` and `port_time_t` by value, stores them, and never calls a framework API or `delay()`.
**When to use:** any logic that touches hardware but must stay host-testable.

```c
/* Source: lib/port/include/port/gpio.h:40-45, lib/port/include/port/time.h:20-27 */
typedef struct port_gpio {
    port_status_t (*set_mode)(void *ctx, uint8_t pin, port_gpio_mode_t mode);
    port_status_t (*write)(void *ctx, uint8_t pin, port_gpio_level_t level);
    port_status_t (*read)(void *ctx, uint8_t pin, port_gpio_level_t *level);
    void *ctx;
} port_gpio_t;

typedef struct port_time {
    uint32_t (*now_ms)(void *ctx);
    void *ctx;
} port_time_t;
```

### Pattern 3: Composition root only in `src/main.cpp`

**What:** `setup()` builds the adapters once; `loop()` calls a non-blocking `controller_tick()`. File-scope storage is acceptable here because Arduino requires the objects to outlive `setup()` (`templates/homework-arduino/src/main.cpp:18-35`).
**When to use:** always; the native tests never compile `src/`.

### Anti-Patterns to Avoid

- **Logic in `src/main.cpp`:** with `test_build_src = false` it is invisible to `pio test -e native`.
- **`"frameworks": ["arduino"]` in `library.json`:** the native environment silently drops the library (verified failure).
- **`delay()` or `millis()` in `lib/pattern`:** breaks the injected-time seam and the `[env:native]` determinism.
- **A naive anti-parallel pair returned to GND:** it cannot light the second LED on `LOW`; use the half-bridge topology below.
- **Committing the Wokwi token, `firmware.merged.bin`, `.pio/`, or `compile_commands.json`:** gitleaks, LFS, and the generated-files hook.
- **Adding an `hw/` tag:** explicitly out of scope (D-19); the tag is Phase 11.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Native unit-test harness | A custom `main` + assertion macros | Unity 2.6.1 via PlatformIO `test_framework = unity` | Already pinned and proven; discovery, reporting, exit codes. |
| Hardware doubles | Custom structs with function pointers | `host_fake_gpio_port`, `host_fake_time_port` | Contract types are identical to the real ports; signature drift becomes a compile error. |
| Debounce timing | A hand-rolled edge timer | `common_debounce_update` (`lib/common/include/common/timing.h:44-45`) | Handles the three-field candidate/stable state and 32-bit wrap. |
| Firmware merge | A bespoke binary concatenator | Adapted Wokwi `merge_firmware.py` using esptool 5 `merge-bin` | Correct offsets come from `FLASH_EXTRA_IMAGES` and `$ESP32_APP_OFFSET`. |
| Metadata validation | A home-grown YAML parser/checker | `uv run scripts/check_metadata.py` | Schema 2020-12, duplicate-key rejection, provenance, Cyrillic. |
| Scaffolding | Hand-copied template files | `uv run scripts/new_homework … --template arduino` | Atomic, idempotent, validates before writing. |

## Common Pitfalls

### Pitfall 1: The provenance timestamp has no timezone

**What goes wrong:** `check-metadata` fails with `retrieved: '2026-10-23' is not an ISO 8601 timestamp with a timezone`, blocking the commit that flips status to `in-progress`.
**Why it happens:** `datetime.fromisoformat` returns `tzinfo=None` for a date; the checker requires a timezone (`scripts/metadata/contract.py:138-144`). The repository test explicitly lists `"bare date"` as rejected (`scripts/tests/test_homework_metadata.py:339-343`).
**How to avoid:** use `2026-10-23T00:00:00Z` (or `+00:00`); `2026-10-24T20:01:00Z` and `+02:00` are the accepted shapes in the test.
**Warning signs:** the checker passes at `status: planned` (TODO sentinels) and fails only after the status flip. Run `uv run scripts/check_metadata.py homeworks/1_3-police-flasher` before staging.

### Pitfall 2: `frameworks` in `library.json` hides the library from native tests

**What goes wrong:** `pio test -e native` fails with `fatal error: 'pattern/pattern.h' file not found`.
**Why it happens:** the default `lib_compat_mode = soft` checks framework compatibility; a `native` environment has no `arduino` framework, so the LDF skips the library. Verified by changing only that field in the probe.
**How to avoid:** omit `frameworks` and `platforms` (meaning "all"), as the five shared libraries do (`lib/port/library.json:1-7`, `lib/common/library.json:1-8`).
**Warning signs:** the target build succeeds while the native test cannot find the header.

### Pitfall 3: The naive single-GPIO LED pair does not alternate

**What goes wrong:** two LEDs wired anti-parallel between the GPIO and GND light only on `HIGH`; `LOW` lights neither.
**Why it happens:** current cannot flow from GND into a GPIO pin.
**How to avoid:** use the half-bridge realization of D-03:
- 150 Ω from GPIO to node X;
- LED1 anode X, cathode GND (lights on `HIGH`);
- LED2 anode 3V3, cathode X (lights on `LOW`).
When one LED conducts it clamps X at its `Vf`; the other sees `3.3 - Vf ≈ 1.3 V`, below its threshold, so it stays off. Both LEDs must have similar `Vf` (two red LEDs), otherwise brightness is very unequal.
**Warning signs:** one LED never lights; Wokwi shows both off in one state.

### Pitfall 4: The canonical Wokwi merge script fails on `espressif32@8.0.0`

**What goes wrong:** `KeyError: 'tool-esptoolpy'` during the post-build action.
**Why it happens:** platform 8.0.0 renamed the package to `tool-esptool` and ships esptool 5, whose subcommands and flags are hyphenated (`merge-bin`, `--flash-mode`, `--flash-size`).
**How to avoid:** adapt the script (verified):

```python
Import("env")
from os.path import join

def merge_firmware(source, target, env):
    board = env.BoardConfig()
    build_dir = env.subst("$BUILD_DIR")
    merged = join(build_dir, "firmware.merged.bin")
    esptool = join(env.PioPlatform().get_package_dir("tool-esptool"), "esptool")
    images = [(offset, env.subst(path)) for offset, path in env.get("FLASH_EXTRA_IMAGES", [])]
    images.append((env.subst("$ESP32_APP_OFFSET"), str(target[0])))
    cmd = [f'"{esptool}"', "--chip", board.get("build.mcu", "esp32"), "merge-bin",
           "-o", f'"{merged}"',
           "--flash-mode", board.get("build.flash_mode", "dio"),
           "--flash-size", board.get("upload.flash_size", "4MB")]
    for offset, path in images:
        cmd += [offset if isinstance(offset, str) else hex(offset), f'"{path}"']
    env.Execute(env.VerboseAction(" ".join(cmd), "Merging firmware images into %s" % merged))

env.AddPostAction("$BUILD_DIR/${PROGNAME}.bin", merge_firmware)
```

**Warning signs:** the first build succeeds, then the post action raises a `KeyError`; no `firmware.merged.bin` appears.

### Pitfall 5: `wokwi-cli` is token-gated

**What goes wrong:** `Error: Missing WOKWI_CLI_TOKEN environment variable. Please set it to your Wokwi token.`
**Why it happens:** the CLI always requires a CI token, even for a local run.
**How to avoid:** author the scenario and lint the diagram offline (`wokwi-cli lint --offline assets/diagram.json` works and needs no token); defer execution to Phase 7 per D-12, or obtain a token.
**Warning signs:** the CLI exits before loading the firmware; `TOKEN_SET=` in the environment.

### Pitfall 6: `diagram.json` is looked up in the project root

**What goes wrong:** `wokwi-cli . --scenario scenario.yaml` reports a missing diagram when the file is at `assets/diagram.json`.
**Why it happens:** the default is `diagram.json` next to `wokwi.toml`; the CLI needs `--diagram-file assets/diagram.json`.
**How to avoid:** pass the option explicitly in every command and record it in the README/report.
**Warning signs:** the CLI starts but cannot find the diagram.

### Pitfall 7: Wokwi pin names are not `esp:3V3` or `esp:43`

**What goes wrong:** lint fails with `invalid-pin`.
**Why it happens:** the board part exposes `3V3.1`, `3V3.2`, `GND.1`..`GND.4`, `RST`, `RX`, `TX`, and GPIO numbers; UART0 is not exposed as `43`/`44`, and there is no bare `3V3`.
**How to avoid:** use the pin list emitted by lint: `0-21`, `35-48`, `3V3.1`, `3V3.2`, `GND.1`..`GND.4`, `RST`, `RX`, `TX`. Use `esp:TX`/`esp:RX` for the `$serialMonitor` connections.
**Warning signs:** only one connection fails; the rest of the diagram lints.

### Pitfall 8: Overriding `extra_scripts` drops the inherited compiledb hook

**What goes wrong:** `compile_commands.json` stops updating for the target build.
**Why it happens:** `extends` replaces list options wholesale; the shared section supplies `extra_scripts = pre:../../scripts/pio/compiledb.py` (`platformio.shared.ini:16`), and a child value wins wholesale (`scripts/check_architecture.py:419-444` documents the same inheritance semantics).
**How to avoid:** repeat both entries:

```ini
extra_scripts =
    pre:../../scripts/pio/compiledb.py
    post:merge_firmware.py
```

**Warning signs:** no `compile_commands.json` at the project root after `pio run`.

### Pitfall 9: The fake button reads "pressed" by default

**What goes wrong:** a controller test sees a press on the first tick without any input.
**Why it happens:** `host_fake_gpio_reset` zeroes `level[]`, and `PORT_GPIO_LOW = 0`; an `INPUT_PULLUP` button at rest should read `HIGH`, but the fake does not model the pull-up.
**How to avoid:** set `fake.level[BUTTON_PIN] = PORT_GPIO_HIGH` before the first tick; drive it `LOW` to press.
**Warning signs:** a debounce test fires immediately at `t=0`.

### Pitfall 10: `[env:native]` compiles with `-Werror`

**What goes wrong:** an unused parameter or a signed/unsigned comparison fails the native suite.
**Why it happens:** the native env repeats `-Wall -Wextra -Werror` (`templates/homework-arduino/platformio.ini:26-30`).
**How to avoid:** keep the pure library warning-clean; cast unused parameters to `(void)`.
**Warning signs:** the target build is green but the native test build fails.

### Pitfall 11: Committing build output or a binary

**What goes wrong:** `no-generated-files` fails, or a `.bin` is captured by LFS.
**Why it happens:** `.pio/` and `compile_commands.json` are gitignored but `git add -f` bypasses that; `*.bin` and `*.elf` are LFS filters (`.gitattributes:9-10`).
**How to avoid:** never add `.pio/`, `firmware*.bin`, or `compile_commands.json`; stage explicit paths.
**Warning signs:** `git status` shows `.pio/` after a `git add -A`.

### Pitfall 12: The provenance cross-check and the sentinel are status-gated

**What goes wrong:** `source.reference: TODO` or a `TODO` in `task.md` frontmatter is rejected once `status` is `in-progress`; a URL mismatch between `homework.yaml` and `task.md` is an error, not a warning.
**Why it happens:** `scripts/metadata/contract.py:240-246,280-301`.
**How to avoid:** flip the status and all four provenance fields in the same commit; keep the two URLs identical.
**Warning signs:** the scaffold passes, the status-flip commit fails.
