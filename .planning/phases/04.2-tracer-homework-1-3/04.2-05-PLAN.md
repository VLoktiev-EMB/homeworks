**Evidence is hybrid (D-11):** the real board for build, flash, and serial, plus three real
measurements — blink period, LED current, and supply voltage — and `Vf` in the multimeter's
diode mode. This plan runs with `autonomous: true`: it uses only evidence already present in
the session — a bench reading the user supplied verbatim, or a serial log from the running
firmware. It never asks a question and never invents a value. If no bench evidence was
supplied, every bench quantity becomes `not measured` with the fixed reason
`bench equipment offline during automated tracer run`, and the report states
`No measured values were captured in this session.` `not measured` is an acceptable and
expected value, not a failure.

**The `measured` prefix is the honesty mechanism.** A `measured` row's value cell must begin
with `user-reported:` or `serial-log:`. That makes every such value quotable back to a human
report or a log line, and it gives Phase 7 a single string to audit.

**The five labels are fixed by D-13.** `measured`, `calculated`, `simulated`, `datasheet`, and
`not measured`. `observed` is not a sixth label; D-14's debounce result is the single qualified
form `measured (observed)` and the distinction is explained in the methodology.

**The simulation is pending.** The Wokwi scenario was authored and linted but not executed
because `WOKWI_CLI_TOKEN` is absent. Any expected timing derived from the scenario is
`simulated (expected, not observed)`. Do not upgrade it.

**The implementation commit:** the ledger uses the same short hash recorded in the report's
metadata table in plan 04. If the code changed after that record, refresh both in the same
commit; the verify asserts they agree.

**Half-bridge limits to record:** the all-off INPUT frame is high-impedance, not a driven dark
state, so the off LED's node voltage is `not measured` with the floating-node reason; and SOLID
on one pin lights only the HIGH-side LED. Both belong in the decision appendix and the
traceability matrix.

**No new packages.**
