**The log is a synthesis, not a diary.** Every entry already records what happened; this plan
turns the entries into decisions. A candidate that names no owning phase is either mapped now
or explicitly rejected with a reason. The automation rule in ROADMAP.md is literal: an
automation with no entry in the log is not built. If an earlier step's friction was never
logged, reconstruct it only from that plan's SUMMARY and commit; if it cannot be reconstructed,
record `not captured during the step` in the `what hurt` cell and say so, rather than inventing
an event.

**The gate includes the shared suite.** `AGENTS.md`'s quick-start runs both the affected
project and `pio test -d tests -e native`, so this phase's gate does too. The offline Wokwi lint
is re-run here as the last cheap proof that the diagram still parses.

**The D-20 fields are the contract:** step, what hurt, frequency, cheap fix, automation
candidate, what worked, and minutes spent. Do not collapse them into prose.

**The D-09 review is a human checklist, not a machine check.** Record its result in the
prepared pull-request body and in the report's decision appendix. The three questions are: no
verbatim sentence, no distinctive phrasing, and no original file committed.

**No tag.** D-19 is explicit; the tag belongs to Phase 11. `scripts/tag_homework.sh` is not run
in this phase.

**Branch and pull request:** branch handling is the user's. Prepare the commit set and the
pull-request body; the user pushes, opens the pull request through the template, and confirms
CI. The end-of-phase human check records that confirmation.

**No new packages.**
