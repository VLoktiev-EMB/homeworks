## Decisions Made

- **The pins did not change.** The three SHAs resolved at planning time were revalidated live
  and matched exactly, so the workflow carries the plan's values rather than a refreshed set.
- **The workflow is deliberately smaller than a full gate.** It runs only the two D-18 commands;
  the metadata and architecture checks stay in pre-commit and the phase gate, and the omission is
  both asserted by the verify and recorded as F-16.
- **The timeout is 45 minutes, not 30.** Without a `~/.platformio/packages` cache a cold runner
  downloads the platform, toolchain, Arduino core, and Unity; caching the package directory and
  then tightening the timeout is a Phase 8 candidate, not a D-18 exception.
- **The shared ini stays unchanged.** A well-formed homework inherits the three shared
  environments and needs no per-homework entry, which is the finding Phase 5's generator consumes.
- **The README links the directory path.** The display name can change without breaking the link,
  and the Task 2 verify asserts the path form.
- **The IDE drift is recorded, not committed.** Adding the workspace folder made the PlatformIO
  IDE generate `.gitignore` and `.vscode/` in the homework directory; those are generated output,
  so they were left untracked and the integration commit staged only the three intended paths.

## Issues Encountered

- Adding the workspace folder caused the running PlatformIO IDE to create
  `homeworks/1_3-police-flasher/.gitignore` and
  `homeworks/1_3-police-flasher/.vscode/{c_cpp_properties,extensions,launch}.json` concurrently.
  The inner `.gitignore` does not cover `extensions.json`, so `git status` reports the whole
  `.vscode/` directory as untracked. The files are generated output; they were deliberately not
  staged, and the repository has no rule for an inner homework `.vscode/`. Recorded as F-18.
- The workflow has not run on GitHub yet. Local revalidation proves the three SHAs resolve, but
  only a runner can confirm the job and the cold-run duration; the first `workflow_dispatch` run
  is the recorded follow-up (F-17).
- `gsd_run` (and `gsd-tools`) is not installed in this environment, so the STATE.md and ROADMAP.md
  updates were applied by direct edit with the same values the state handlers would have written:
  position advanced to plan 7 of 7, the per-plan metric row appended, the decision bullets added,
  and the roadmap plan count moved to 6/7. REQUIREMENTS.md was not marked, because the shared-ID
  gate keeps INV-03 and PILOT-01 open while plan 07 declares them without a summary.
