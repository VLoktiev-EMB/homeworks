**Verified Wokwi facts:** pin names are `esp:0`..`esp:21`, `esp:35`..`esp:48`, `esp:3V3.1`,
`esp:3V3.2`, `esp:GND.1`..`esp:GND.4`, `esp:RST`, `esp:RX`, `esp:TX`. There is no bare
`esp:3V3` and no `esp:43`/`esp:44`; the serial monitor uses `esp:TX` and `esp:RX`. The board
part is `board-esp32-s3-devkitc-1`. Resistor terminals are `1` and `2`; LED terminals are `A`
and `C`; the pushbutton terminals are `1.l` and `2.l`.

**The merge script is not the published one.** `espressif32@8.0.0` renamed the package to
`tool-esptool` and ships esptool 5, whose subcommand is `merge-bin` and whose flags are
`--flash-mode` and `--flash-size`. The published script raises `KeyError: 'tool-esptoolpy'`
(RESEARCH Pitfall 4). Use
`env.PioPlatform().get_package_dir("tool-esptool")`, offsets from `FLASH_EXTRA_IMAGES`, and
`$ESP32_APP_OFFSET`. Write only `$BUILD_DIR/firmware.merged.bin`.

**`extra_scripts` replaces the inherited list wholesale.** Repeating
`pre:../../scripts/pio/compiledb.py` is required or the target build stops producing
`compile_commands.json` (RESEARCH Pitfall 8).

**The token is absent in this environment.** `wokwi-cli lint --offline` works; execution exits
before loading firmware with a missing `WOKWI_CLI_TOKEN`. Per D-12, record and defer.

**Package installs:** none.

## Threat model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SCons build script to host filesystem and network | `extra_scripts` runs arbitrary Python at build time with the developer's permissions. |
| Build directory to git history | A firmware image is a large binary that must never be committed. |
| External simulator to report claims | A simulator result would be evidence only if it was actually observed. |
| Credential to repository | The Wokwi token authorizes CI minutes and must stay out of the tree. |
