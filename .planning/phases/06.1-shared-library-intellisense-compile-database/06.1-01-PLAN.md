<objective>
Give clangd a compile command for every shared-library source, by generating one root `compile_commands.json` from three existing PlatformIO databases and adding the root `.clangd` fragment those files need.

Purpose: Phase 6 shipped the multi-root workspace, the wrapper, the per-project `.clangd` files and the onboarding guide, but clangd resolves a file by walking upward, and there is neither a database nor a fragment above `lib/`. Every `.c` under `lib/` therefore reports `Arduino.h` file not found and unknown `port_*` types, which contradicts the Phase 6 goal for the `lib` folder. The sibling databases already contain the right commands; only discovery is missing. `.planning/notes/lib-intellisense-clangd-diagnosis.md` is the diagnosis and `.planning/todos/pending/2026-10-26-add-lib-intellisense-compile-database.md` is the agreed solution shape.

Output: `scripts/gen_clangd_db.py`, a root `.clangd`, the generated (untracked) root database, an extended compiler allowlist in the wrapper, the template-scoped ignore rules its ESP-IDF input requires, the coverage and failure tests, the guide section, and one decision-table row.

Boundary to state plainly in the SUMMARY: one compile command per path is a physical constraint, so `lib/common` and `lib/port` are compiled in three environments and the native context is chosen deliberately — this is a representative choice, not a wrong-command defect. `lib/port` is header-only: it has no entry of its own, and clangd serves its headers by inferring a command from the nearest native entry; the acceptance therefore checks its public header rather than a source. `templates/homework-espidf/src/main.cpp` still reports three errors in this environment and is out of scope; that residual is recorded, not claimed fixed.
</objective>
