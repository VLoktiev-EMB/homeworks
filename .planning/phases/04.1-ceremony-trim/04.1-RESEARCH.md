# Phase 4.1: Ceremony Trim - Research

**Researched:** 2026-10-25
**Domain:** Repository de-governance — deterministic deletion and rewrite of tooling, CI, docs, and the agent rulebook
**Confidence:** HIGH (every claim below was read or executed in this repository this session; nothing depends on external documentation)

## Summary

This is not a feature phase. It is a deletion-and-rewrite phase whose two hardest
requirements are "the remaining gates still pass" and "no dangling references". The
research therefore produced three artifacts the planner needs: an **executed baseline**
(310 Python tests green, 73 Unity cases green, 8 pre-commit hooks green, smoke builds at
7.3 s and 26.8 s), a **dependency graph of the deletion set** with two hard blockers, and a
**line-level inbound-reference inventory** that extends past the four paths named in
success criterion 5.

Two blockers make the trim non-mechanical. `test_homework_metadata.py` — which survives —
imports `EXPECTED_PATTERN` from `test_homework_id.py`, which is on the delete list. And
both surviving test modules read `scripts/metadata/allowlist.json`: `contract.py` through
`load_allowlist`, `temp_root.build_root` through an unconditional `shutil.copy2`. Delete
the allowlist without repairing those three call sites and **every** surviving test fails
with `ModuleNotFoundError` or `FileNotFoundError`. These repairs are Wave 0, not cleanup.

A second class of findings is a conflict the planner must resolve explicitly, not silently:
success criterion 5 requires zero dangling references in `docs/`, but the todo forbids
rewriting the ADRs, and four ADRs name deleted paths (`policy/repository.json`,
`scripts/check_policy.py`, `NOTICE`, `LICENSES/`). The resolution consistent with both is
that an ADR body is archive and is exempt from the sweep; the dead mechanism is recorded in
the new table's `Status` column instead. Relatedly, SC4 names `python3
scripts/check_metadata.py`, which **cannot pass today** — the script is mode 644 and its
imports need PyYAML/jsonschema, so the only working invocation is `uv run
scripts/check_metadata.py`.

**Primary recommendation:** Repair the three decoupling points first (move
`EXPECTED_PATTERN`, strip the allowlist from `contract.py`/`check_metadata.py`/`temp_root.py`,
surgically remove the six allowlist tests from `test_homework_metadata.py`), prove the
suite green, then delete meta-tooling and its tests in one atomic block, then rewrite
`AGENTS.md`/`README.md`/`docs/decisions/README.md` last — because three of the deleted test
modules are the current assertions on those files' old shape.

### Hard blockers (must be repaired before any deletion)

**B1 — cross-module constant.** `scripts/tests/test_homework_metadata.py:35`:
`from scripts.tests.test_homework_id import EXPECTED_PATTERN`. The literal is
`EXPECTED_PATTERN = r"^[0-9]+_[0-9]+-[a-z0-9-]+$"` (`test_homework_id.py:26`). Deleting the
module without moving the constant raises `ModuleNotFoundError` at collection time, so the
entire surviving module contributes **zero** tests. `test_homework_metadata.py:927-953`
(`test_canonical_id_literal_is_identical_in_four_places`) must become a three-place check
(schema `id.pattern`, `contract.py` `HOMEWORK_ID`, `AGENTS.md` span) and be renamed
accordingly. `scripts/metadata/contract.py:72-74` still documents the four-place invariant
and must lose the `EXPECTED_PATTERN` clause.

**B2 — allowlist copy in the harness.** `scripts/tests/temp_root.py:79-81`:

```python
    allowlist = root / ALLOWLIST_PATH
    allowlist.parent.mkdir(parents=True, exist_ok=True)
    shutil.copy2(repository / ALLOWLIST_PATH, allowlist)
```

Unconditional. `ScaffoldTestBase.setUp` calls `build_root` for every test in the module, so
the allowlist deletion fails all of `test_new_homework.py`. `ALLOWLIST_PATH` itself is
declared at `temp_root.py:33`. Remove the constant and the three lines.

**B3 — the same file in the other survivor.** `test_homework_metadata.py:202-206` copies
`scripts/metadata/allowlist.json` into every fixture root. Remove the block; also remove
`write_allowlist` (lines 232-239) and the six allowlist tests.

## `scripts/tag_homework.sh`

Five preconditions today (200 lines total, lines 100-177):

1. ID matches `^[0-9]+_[0-9]+-[a-z0-9-]+$` (`ID_PATTERN`, line 36) — usage error, exit 2.
2. `origin/HEAD` resolves and `refs/remotes/origin/<default>` exists.
3. `git cat-file -e "$base:homeworks/$id"` — the directory exists **at that commit**, not in
   the working tree.
4. No local tag and no remote tag with that name.
5. A merged PR for branch `hw/<id>` targeting the default branch, via `gh pr list`.

`TAG_HOMEWORK_SKIP_REMOTE=1` bypasses the fetch, the remote-tag lookup, and the merged-PR
check. Its **only** consumer is `scripts/tests/test_tag_homework.py` (deleted), so it becomes
dead configuration.

### Minimal replacement that keeps AGENTS.md's tag rule true

The rule that must survive is: *a `hw/<id>` tag is created only after the homework PR is
merged and is never moved.* Git's own behaviour already enforces the last half:

- `git tag hw/<id> <commit>` fails if the local tag exists.
- `git push origin refs/tags/hw/<id>` is rejected as non-fast-forward if the remote tag points
  elsewhere, so a published tag cannot be moved without `--force`.

So the safe minimal form is:

```bash
set -euo pipefail
id="$1"
[[ "$id" =~ ^[0-9]+_[0-9]+-[a-z0-9-]+$ ]] || { echo "bad id: $id" >&2; exit 2; }
base="$(git rev-parse "origin/$(git symbolic-ref --short refs/remotes/origin/HEAD)")
git tag "hw/$id" "$base"
git push origin "refs/tags/hw/$id"
```

What is genuinely lost: the merged-PR gate and the "directory exists at that commit" gate
become review/process rules rather than machine gates. AGENTS.md's wording must be rewritten
to match, otherwise SC1 ("the tag preconditions are gone") and the rule claim contradict each
other. Recommendation: keep the script (five lines), drop `TAG_HOMEWORK_SKIP_REMOTE` and the
`gh` dependency; do not document a bare command, because `origin/main` is not always the
default branch and a hand-typed commit is the one thing the script exists to prevent.

## Common Pitfalls

### P1 — SC5 ("no dangling references in `docs/`") contradicts "do not rewrite the ADRs"

Four ADRs name deleted paths: ADR-0003 (`policy/`, `check_policy.py`), ADR-0004 (`REUSE.toml`,
`NOTICE`, `LICENSES/`), ADR-0011 (`policy/repository.json`, `check_policy.py`), and ADR-0005/
0006 (`NOTICE`). A literal SC5 sweep fails. **How to avoid:** define the sweep as covering
*live* documents — `README.md`, `AGENTS.md`, `.github/`, and `docs/decisions/README.md` — and
state in the new table's preamble that "ADR bodies are historical; a path named in a
superseded record may no longer exist." Without that sentence the archive reads as broken
documentation. Do not rewrite ADR bodies.

### P2 — Deleting the allowlist breaks both surviving test modules

Covered in B2/B3. The symptom is a hard `FileNotFoundError` in every scaffold test and an
`exit code 2` in every metadata fixture test, not a soft degradation. This is the single most
likely way to fail SC4.

### P3 — `test_homework_id.py` is a transitive dependency of a survivor

Covered in B1. Symptom: `ModuleNotFoundError` at collection, so the survivor reports zero
tests and `discover` still exits non-zero.

### P4 — SC4's literal `python3 scripts/check_metadata.py` cannot pass

Mode 644, no `yaml` in the system interpreter. Evidence: `ModuleNotFoundError: No module
named 'yaml'` exit 1; `./scripts/check_metadata.py` → `permission denied` exit 126. **How to
avoid:** reword SC4 to `uv run scripts/check_metadata.py` (exit 0). The same defect is in the
todo's Verify section; correct it in one place and cite it. Do not "fix" it by making the
script executable — its imports would still fail outside `uv`.

### P5 — `AGENTS.md` must keep exactly one anchored backticked pattern

`test_homework_metadata.py:937-947` asserts the file contains **exactly one** backticked span
matching `` `^…$` ``, and line 949 asserts it equals the schema pattern. Currently
`grep -oE '`\^[^`]*\$`' AGENTS.md` returns exactly one:
`` `^[0-9]+_[0-9]+-[a-z0-9-]+$` ``. **The rewrite must not add a second anchored pattern**
(for example a commit-subject regex or a branch-name regex) or the kept test fails on a
technicality unrelated to the trim.

### P6 — The `reuse` job has no required-status-check coupling, but the fixture does

`policy/ruleset-main.json` declares `"required_status_checks": []`, so removing the job breaks
no required check. However `scripts/tests/fixtures/ruleset-live.json` is the captured GET body
for `test_check_policy.py` and must be deleted with it — otherwise it is an orphaned fixture
of a deleted checker.

### P7 — The golden fixtures are load-bearing

`scripts/tests/fixtures/golden/homework-{arduino,espidf}/` (17 files) is read by the **kept**
`test_new_homework.py` (`GOLDEN_ROOT`, line 29; `assert_golden`, line 105). Only
`fixtures/ruleset-live.json` is orphaned. Deleting the whole `fixtures/` directory would break
the retained scaffold test.

### P8 — `.gitattributes` and `.gitignore` need no change

No deleted path has an LFS-tracked extension (`.pdf .step .stl .fzz .zip .bin .elf .vcd`);
`policy/*.json`, `REUSE.toml`, `NOTICE`, `LICENSES/*.txt`, and the PR `.md` templates are all
ordinary git objects. `.gitignore` contains no reference to `policy`, `LICENSES`, `NOTICE`,
`REUSE`, or `allowlist` (verified). The `no-generated-files` hook's path list is unrelated to
the deletion set. Expect "no action" here — but verify it rather than assume it.

### P9 — Two comments in live files name deleted tests

`.pre-commit-config.yaml:62-65` ("`scripts/tests/test_metadata_deps.py` parses all three
declarations as text and fails when they diverge") and `scripts/metadata/contract.py:72-74`
(``EXPECTED_PATTERN` in `scripts/tests/test_homework_id.py`…`). Neither is in SC5's four
paths; both become the only dangling references in the tree if skipped.

### P10 — `.claude/CLAUDE.md` has a generator-owned GSD block

Lines 19-32 are wrapped in `<!-- GSD:workflow-start … -->` / `<!-- GSD:workflow-end -->` and
the file states the inner text must be preserved verbatim. It restates "start work through a
GSD command". This is *compatible* with the proportional rule (every tier is a GSD command),
so the safest plan is: leave the block alone, put the tiers in `AGENTS.md`, and rely on the
documented precedence ("This file wins" / `@AGENTS.md` on line 1). Editing inside the block
would be reverted by the next generator run anyway. If the plan chooses to delete the block,
delete it wholesale rather than editing its text, and note that a future generator run
re-adds it.

### P11 — The licence change is forward-only

ADR-0004: "a published license grant cannot be withdrawn". Removing `REUSE.toml` means
*new* content is MIT only; content already published under CC-BY-4.0 keeps that grant in
history. The plan should not claim the repository was "always MIT". This is a compliance
statement, so treat it as `[ASSUMED]` user intent unless confirmed (A1).

### P12 — `uv` needs a writable cache for the suite

In a sandboxed or read-only-cache environment, `uv run` inside the tests fails with
`Could not acquire lock … Operation not permitted` and produces 30 failures + 2 errors that
look like repository breakage. Set `UV_CACHE_DIR` to a writable path when recording the
before/after numbers, or the "after" run will be misread.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Cyrillic detection | A hand-maintained Unicode range list or a `grep -P` in a shell hook | The existing `is_cyrillic_char` (Unicode-name based, `contract.py:154`) | It already covers the Supplement, Extended-A/B/C/D, and historic blocks; a range set silently misses blocks and the existing tests at 395 prove the extended cases |
| Tag-existence safety | New precondition logic | `git tag` and `git push` default refusal semantics | Both already refuse to create/move an existing tag without `--force`; only the id shape and the target commit need code |
| Dead-reference detection | A permanent `scripts/check_dead_references.py` | A one-shot shell assertion in the phase verification | The decision rule says a check that runs once is not worth committing; a permanent checker is exactly the ceremony this phase removes |
| `/gsd-fast` staging | A fork of the workflow file in the repo | A rulebook rule + a small helper (Route B) | There is no project-local workflow override mechanism; a copied `fast.md` would drift silently |
| Decision-record indexing | A status-index generator or a numbering registry | One Markdown table | The table *is* the index; anything that must be regenerated is the upkeep the trim removes |

**Key insight:** every item on the "don't build" list would reintroduce the recurring cost
that the decision rule measures. The trim's own verification should be a transient
command run, not a new artifact.
