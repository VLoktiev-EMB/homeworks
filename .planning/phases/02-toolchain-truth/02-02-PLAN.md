<objective>
Close the hygiene gap that opens during the first ESP-IDF build: `CMakeLists.txt`,
`src/CMakeLists.txt` and `sdkconfig.<env>` are generated inside the project tree, and without an
explicit rule they either enter the commit or stay untracked (P6, D-23). Extend `.gitignore` in a
way that keeps the authored `sdkconfig` and `sdkconfig.defaults` visible, and bring the test and the
pre-commit hook into line with the new rule.

Purpose: `AGENTS.md` requires generated files to be never committed; `.gitignore` is the first
layer, and the `no-generated-files` hook is the second. Updating only `.gitignore` leaves
`git add -f` able to bypass both.

Output: a scoped `.gitignore` block with an explicit negation, an updated
`scripts/tests/test_gitignore.py`, and an extended `no-generated-files` hook with its reason
recorded in the configuration.

Note on the requirement tag: this plan supports FOUND-09 rather than delivering the pin itself.
The phase defines only two requirement IDs and the plan contract rejects an empty `requirements`
field, so FOUND-09 is carried here with this explicit qualifier: the ESP-IDF half of the pinned
N16R8 toolchain writes generated files into the project tree, and without these ignore rules the
commit that proves FOUND-09 cannot keep them out of history. See the ledger below.
</objective>
