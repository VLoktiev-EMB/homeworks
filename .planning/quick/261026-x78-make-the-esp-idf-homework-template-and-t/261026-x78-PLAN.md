<objective>
Make the ESP-IDF homework template and the `new-homework` skill ship pure C, while the Arduino template stays C++.

Purpose: ESP-IDF's native API is C and `app_main` is a plain C symbol, so the current `.cpp` entry point exists only to declare a C++ linkage wrapper around C code. The template, its golden tree, the FOUND-01 test map and the skill's intake rule all currently hard-code the C++ assumption, so they must move together. `schema/homework.schema.json` already permits `language: c`, `lib/espidf/**` is already C, and the template's native env builds with `-std=c11`; only the entry point and the metadata say otherwise.

Scope note: Phase 2's decision that fixes a C++ entry point governs the shared smoke project `homeworks/0_0-toolchain-smoke`, which must also compile under Arduino core 3.x and relies on C++ linkage for `setup`/`loop`. It does not govern `templates/homework-espidf`, which has no Arduino core. The decision row written by Task 3 records that distinction. Arduino sources, `homeworks/1_3-police-flasher`, `platformio.shared.ini`, `templates/views/` and `.planning/phases/**` are out of scope.

Output: a C ESP-IDF template and its golden tree, a per-template FOUND-01 assertion, corrected skill prose and its regenerated mirror, one decision-table row, and a green local gate. The 09-08 dry run is a separate follow-up and is not re-run here.
</objective>
