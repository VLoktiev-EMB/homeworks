<objective>
Make the ESP-IDF homework template and the `new-homework` skill ship pure C, and delete the stored golden fixture trees in favour of property assertions against the live template.

Purpose: ESP-IDF's native API is C and `app_main` is a plain C symbol, so the template's `.cpp` entry point exists only to wrap C code in a C++ linkage declaration. Separately, the two golden trees are 19 committed files, 13 of them byte-identical duplicates of their template source; every intentional template edit costs two edits and the copies can drift. Removing them replaces a stored snapshot with a property check of the input the scaffold actually reads.

Why property assertions replace the golden trees: a stored snapshot proves "the output equals what we stored", but it does not prove the output matches the template the scaffold consumes, and it silently rots when the template changes without the fixture. The replacement is at least as strong on three axes. File-set equality proves no file is added or lost. Byte equality for every placeholder-free template file proves the renderer is a no-op on ordinary content — this catches encoding, newline and substitution corruption without any stored bytes. Per-document assertions prove the four substituted files (`homework.yaml`, `README.md`, `task.md`) carry the expected values and no leftover token. The guarantee that is lost is a human-readable unified diff for an intentional change; it is replaced by the test naming the exact differing relative path and source. The decision row records this trade-off.

Scope note: Phase 2's decision that fixes a C++ entry point governs the shared smoke project `homeworks/0_0-toolchain-smoke`, which must also compile under Arduino core 3.x and relies on C++ linkage for `setup`/`loop`. It does not govern `templates/homework-espidf`, which has no Arduino core. Arduino sources, `homeworks/1_3-police-flasher`, `platformio.shared.ini`, `templates/views/` and `.planning/phases/**` are out of scope. The 09-08 dry run is a separate follow-up and is not re-run here.

Output: a C ESP-IDF template, a fixture-free scaffold suite built on live-template properties, corrected skill prose and its regenerated mirror, one decision-table row, and a green local gate in one atomic commit.
</objective>
