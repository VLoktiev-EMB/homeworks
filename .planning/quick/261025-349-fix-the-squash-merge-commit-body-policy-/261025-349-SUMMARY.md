## Decisions Made

- **Use `PR_TITLE` + `PR_BODY`, not the plan's `COMMIT_OR_PR_TITLE` + `PR_BODY`.** GitHub
  rejects the latter pair with HTTP 422 `invalid_squash_commit_setting_combo`; the accepted
  pair still puts the reviewed PR body in the permanent record and additionally removes the
  single-commit title exception.
- **Keep `c904062` untouched.** The fix changes future squash composition only, consistent
  with the AGENTS.md no-rewrite rule.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Replaced the plan's invalid squash-merge pair with an API-valid pair**
- **Found during:** Task 3 (apply the committed policy to GitHub)
- **Issue:** The plan mandates `squash_merge_commit_title=COMMIT_OR_PR_TITLE` together with
  `squash_merge_commit_message=PR_BODY`. `python3 scripts/check_policy.py --apply` failed with
  exit 2 and `gh: Validation Failed (HTTP 422)`. A minimal PATCH returned: "Sorry, invalid
  setting combination. The following are valid combinations for the squash commit title and
  message: PR_TITLE and PR_BODY, PR_TITLE and BLANK, PR_TITLE and COMMIT_MESSAGES,
  COMMIT_OR_PR_TITLE and COMMIT_MESSAGES. (invalid_squash_commit_setting_combo)". The plan's
  must-have truth is therefore unachievable at the API.
- **Fix:** Declared `PR_TITLE` + `PR_BODY`. It is the only valid pair that keeps the reviewed
  PR body, satisfies every decision driver, and removes the single-commit commit-subject
  exception instead of preserving it.
- **Files modified:** `policy/repository.json`,
  `docs/decisions/0011-squash-merge-commit-message.md`
- **Verification:** `python3 scripts/check_policy.py --apply` and `--check` both exit 0 with
  PASS on both keys; live GET prints `PR_TITLE PR_BODY`.
- **Committed in:** `f83da77` (Task 3 commit)
